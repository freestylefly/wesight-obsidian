# GitHub 团队协作

在 WeSight 侧栏点击头像，可查看当前仓库与分支、待拉取和待推送数量，执行「立即拉取」「推送提交」，或打开「仓库同步设置」「同步记录」。未登录 WeSight 时，登录按钮旁的本地头像也提供同步入口。

当知识库有尚未提交的文件修改时，推送入口显示「提交并推送」。点击后确认本次提交的文件和提交说明，再执行提交、拉取并合并团队更新、推送。未选择的文件和其他工具暂存的内容保持原样。如果提交后的网络请求或合并失败，本地提交会保留，并显示尚未推送的原因。此流程可以在自动提交关闭时使用。

提交窗口会在本机读取所选文件与当前提交的差异，自动填写具体的提交摘要。可点击「重新总结修改」更新摘要，也可点击「AI 总结」调用当前默认 Agent 和模型配置，将所选文件的有限差异发送给该模型，生成更自然的提交说明。未选择和被排除的文件不会进入总结，较大的差异会截断并明确标记。AI 总结只生成文字，关闭窗口会取消生成；生成失败或期间手动填写说明时，会保留原有输入。生成完成后，仍需点击「提交并推送」才会执行 Git 写操作。

## 连接已有仓库

当前知识库需要位于本地 Git 仓库中，当前分支需要设置远程跟踪分支（upstream）。WeSight 使用系统已有的 Git 和登录凭据，支持 HTTPS 与 SSH，不存储 GitHub 密钥。GitHub、远程仓库权限和分支规则沿用本机 Git 的配置。

在「设置 → WeSight → 仓库同步」点击「检测连接」，获取最新的远程提交数量。未安装 Git、缺少 upstream、网络异常或认证失败时，面板会显示具体的处理提示。

## 自动同步

自动化首次使用默认关闭。选择需要的开关后，点击「保存设置」生效。

1. 自动拉取：每 1、5、15 或 30 分钟检查团队更新，并合并到当前分支。有未提交的本地修改时暂停拉取。
2. 打开知识库时拉取：启动此知识库时拉取一次，与定时拉取独立控制。
3. 自动推送：定时推送当前跟踪分支已有的提交。远程有新提交时，需要先拉取；可同时开启自动拉取以完成这一流程。
4. 自动提交：停止编辑 1、5、10 或 15 分钟后提交符合范围的文件。只有同时开启自动推送，修改才会自动上传。自动提交使用独立的空闲计时，检查频率较长时也能按空闲时间提交。

开启自动提交后，设置页会显示当前将纳入提交的修改文件。默认排除 `.wesight/`、`.env`、`.env.*`，并始终排除当前 Obsidian 配置目录。支持按知识库相对路径配置排除规则，目录以 `/` 结尾，支持 `*`。`.gitignore` 会继续生效。知识库位于较大仓库的子目录时，自动提交仅纳入知识库目录中的修改。

排除规则作用于自动提交。已经提交的文件会随提交记录一起推送，包括手动提交到 Git 的文件。团队的长期忽略规则应在 `.gitignore` 中维护。

自动提交信息可包含 `{device}` 和 `{time}`。手动暂存的修改由你处理，WeSight 会暂停自动提交，避免将其他 Git 工具的暂存内容混入自动提交。

## 同步状态与恢复

拉取允许快进或合并独立的团队修改。同一位置发生冲突时，Git 保留冲突文件，WeSight 暂停自动同步并提示处理。通过 Git 完成冲突处理与提交后，自动同步在后续检查中恢复。拉取过程会保留本地未提交内容及发生路径重叠的未跟踪文件。

WeSight 的同步操作串行执行，不会执行强制推送、自动 stash 或 reset。外部 Git 工具执行合并、变基或暂存时，自动化会暂停相应操作。切换分支、修改远程或移动仓库后，自动同步会暂停，需要在设置页重新保存当前目标。断网时跳过自动同步和自动提交；运行中的远程连接遇到明确网络故障或超时时安静跳过，不弹窗，也不写入同步记录。历史中的自动同步网络失败提示会自动过滤。网络恢复后在后续检查中继续同步；认证、权限及合并冲突等错误仍保留提示和记录，同一自动同步错误只提示一次。

配置和最近 30 条操作记录保存在本机 WeSight 目录的 `git-sync/` 子目录，按知识库路径隔离。配置不会随知识库上传给其他设备。每台协作电脑分别设置自动化。Obsidian 关闭或插件停用后，同步停止。

## 快捷命令

命令面板提供「立即拉取当前仓库」「推送当前仓库提交」「检查当前仓库远程更新」「打开仓库同步设置」，可在 Obsidian 快捷键设置中绑定。
